# ADR-004: Langfuse Deployment Architecture

**Date:** 2026-08-28  
**Status:** Accepted

## Context

The project needs a Langfuse instance for development, testing, and evaluation. Developers must be able to use it without paying for cloud credits and without committing credentials to the repository.

## Langfuse v3 Self-Hosted Architecture

The current Langfuse self-hosting architecture (v3) requires the following services:

| Service      | Purpose                                              | Port  |
|-------------|------------------------------------------------------|-------|
| `langfuse`  | Next.js web UI + REST API (ingestion, management)    | 3000  |
| `postgres`  | Primary relational database (users, projects, prompts, datasets) | 5432 |
| `clickhouse`| Columnar trace/event storage for high-volume analytics | 8123, 9000 |
| `redis`     | Background job queue (async trace ingestion pipeline) | 6379 |
| `minio`     | S3-compatible blob storage (media uploads, exports)  | 9001  |

This is the architecture mandated by the official Langfuse docker-compose:  
https://langfuse.com/self-hosting/docker-compose

We follow this exactly — we do not simplify or reduce it.

## Options

### Option A — Langfuse Cloud only

Use https://cloud.langfuse.com without self-hosting.

**Cons:** Requires credentials to get started. Costs money at scale. Developers cannot work offline.

### Option B — Self-hosted only

Always use local Docker Compose.

**Cons:** Cloud mode is useful for production reference; developers may want to use their existing Cloud accounts.

### Option C — Self-hosted as default, Cloud as optional override

Default to local (`http://localhost:3000`). Switch to Cloud by changing three env vars.

**Pros:** 
- No credentials required to start learning.  
- Full feature parity — same SDK, same calls.  
- Cloud integration becomes a configuration test, not a code change.

## Decision

**Option C — self-hosted default, Cloud as optional override**

The three variables that control the mode are:

```env
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_HOST=http://localhost:3000   # change to https://cloud.langfuse.com for Cloud
```

No code changes required to switch. The application code is identical in both modes.

## Consequences

- Milestone 1 implements the full Langfuse v3 docker-compose.
- `make langfuse-up` starts all five services.
- The Langfuse UI is accessible at `http://localhost:3000`.
- Credentials for local Langfuse (generated by the UI on first run) go in `.env` — never committed.
- Milestone 19 documents and tests the Cloud switch.
- If Langfuse is unavailable (`LANGFUSE_ENABLED=false` or network error), the application continues serving — observability is not a hard runtime dependency.
